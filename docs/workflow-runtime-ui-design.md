# Workflow 运行界面设计

## 1. 目标

Workflow 运行页只保留三类核心界面：左侧 Conversation、中央 Workflow 流程图、底部 Task Delegation。顶部栏保持现状。

旧雪景角色运行界面和右侧常驻执行摘要不再参与渲染。节点详情采用渐进展示：未选择节点时不占用空间，点击节点后才在原右侧栏位置出现。

## 2. 页面结构

```text
┌──────────────────────────── 顶部栏（保持不变） ────────────────────────────┐
├──────── Conversation ────────┬──────────────── Workflow Canvas ────────────┤
│ 项目                          │                                             │
│ 会话                          │             居中的真实 Workflow 拓扑        │
│ 历史任务                      │                                             │
│                               │   ┌──────── Task Delegation ────────────┐   │
│ 用户                          │   └─────────────────────────────────────┘   │
└───────────────────────────────┴─────────────────────────────────────────────┘

点击节点后：
┌──────── Conversation ────────┬──────── Workflow Canvas ────────┬─ Detail ─┐
│                               │                                  │          │
│                               │                                  │ 节点详情 │
│                               │      Task Delegation             │          │
└───────────────────────────────┴──────────────────────────────────┴──────────┘
```

- Workflow Canvas 直接复用 Workflow 编辑器的节点、分支、连线、画布和缩放控件，只在节点上叠加运行状态，不维护第二套视觉组件。
- 默认自动居中并适配可视区域，支持平移、缩放和重新居中。
- 详情栏宽度固定在约 440px，出现时流程图重新适配剩余空间。
- 点击画布空白处或详情栏关闭按钮，详情栏收起。
- Task Delegation 始终位于流程图底部，用于选择 Workflow 并启动或停止任务。

## 3. 节点状态

节点以图标、文字和颜色共同表达状态，不能只依赖颜色：

| 状态 | 展示 | 含义 |
| --- | --- | --- |
| Waiting | 空心圆 + 灰色 | 尚未执行 |
| Running | 旋转指示 + 蓝色 | 正在执行 |
| Awaiting approval | 手动确认图标 + 黄色 | 等待人工处理 |
| Completed | 对勾 + 绿色 | 执行成功 |
| Failed | 错误图标 + 红色 | 执行失败 |

当前执行路径允许连线动画，其他连线保持静态；系统启用 `prefers-reduced-motion` 时关闭动画。

## 4. 节点交互

### 4.1 悬停与键盘聚焦

展示只读配置摘要：

- 通用：节点名称、类型、节点 ID。
- Agent：Agent 配置、输入模板。
- LLM：模型、系统提示词、用户提示词、响应格式。
- Tool：工具名称、参数映射。
- Approval：标题、审核说明、审核内容。
- Condition / Loop：条件表达式、最大循环次数。
- End：输出映射。

悬停只用于快速查看；节点可通过键盘聚焦并获得同样信息。

### 4.2 点击

点击后在右侧详情栏展示选中节点的运行详情。新的节点选择直接替换详情内容，不弹出模态框。

同一节点存在多次执行时，详情栏提供“Attempt 1 / Attempt 2”切换，默认显示最近一次。

## 5. 节点详情

### Agent

- 展示该节点接收到的问题。
- 复用 Agent 模式的执行时间线组件展示思考、工具调用和执行过程。
- 运行中按现有流事件增量更新，不另外建立轮询或流连接。
- 完成后展示最终回答。

### LLM

- Question：实际提示词或配置的提示词模板。
- Answer：流式过程存在时实时更新，完成后展示节点结果。
- 可补充模型、耗时和状态信息。

### Tool

- Input：工具名和入参。
- Execution：属于该节点的工具事件时间线。
- Result：工具输出或错误信息。

### Human approval

- 展示待审核内容。
- Approve 可直接提交。
- Reject 必须先填写 feedback，空 feedback 时按钮不可用。
- 提交中禁用操作并显示明确的处理状态；失败时保留输入并展示可恢复错误。

### 其他节点

Start、Condition、Loop、End 使用统一详情结构展示配置、状态、输入、结果、错误和耗时。

## 6. 历史与重试

- 节点多次执行记录从 Workflow 流事件中按 `workflow_node_id` 分组，不额外维护重复状态。
- 当前后端只支持重新运行整个任务，没有从指定节点恢复执行的接口。
- 失败节点首版明确提供“Run workflow again”，调用现有任务重跑能力，不伪装为节点级续跑。
- 后续若补充节点级重试，需要后端提供包含 `workflow_run_id`、`node_id` 和上游状态快照的恢复接口，再将按钮升级为“Retry node”。

## 7. 删除范围

- 删除 BotWorld 雪景 Workflow 运行组件。
- 删除旧 Workflow 右侧摘要卡片组件。
- 删除仅被上述界面引用的地图视口、游戏逻辑和相关样式入口。
- 保留 Workflow 编辑器、Task Delegation、Conversation、Agent 聊天渲染和底层任务流数据处理。
- 不复制一套新的运行状态；新界面读取现有 `workflowSnapshot`、`workflowRun` 和 `eventLog`。

## 8. 性能与可访问性

- React Flow 节点和边由 `workflowSnapshot` 与 `workflowRun` 记忆化生成。
- 流式更新只刷新当前任务和选中节点详情，不渲染旧世界动画。
- 控件提供可见焦点、文本标签和至少 44px 的点击区域。
- 状态不只依赖颜色；动态区域使用 `aria-live="polite"`。
- 动画限制在 `transform`、`opacity` 和执行路径，遵循减少动态效果设置。
